# Lessons

## Prompt 1 — NIM provider migration
- **groq-sdk cannot talk to NVIDIA NIM's gateway** — even with `baseURL` correctly overridden to `https://integrate.api.nvidia.com/v1` and a valid `NVIDIA_API_KEY`, every request returned a plain-text `404 page not found` (not a JSON error), while an identical raw `fetch()` call to the same URL/body returned `200`. The `openai` npm package (NIM's officially documented client) works correctly against the same endpoint with the same request shape. Installed `openai` as a new dependency and used it for `nimClient` instead of reusing `groq-sdk` with a custom baseURL.
- `groqComplete(client, model, messages, maxTokens, temp)` is provider-agnostic — it just calls `client.chat.completions.create(...)`, so the same helper works for `nimClient` (OpenAI SDK) without modification, since both SDKs expose the same `chat.completions.create` interface.
- **Fallback-model bug**: the existing `fallbackModel` ternary reused the *original* route's `model` string when falling back to `groq1`/`groq2`. For NIM routes, the model name (e.g. `deepseek-ai/deepseek-v4-flash`) doesn't exist on Groq, so a nim→groq1 fallback would 404. Fixed by special-casing: if the original `provider === 'nim'`, the groq fallback uses `MODELS.LLAMA4` instead of the NIM model string.
- **Missing NVIDIA_API_KEY handling**: `new OpenAI({ apiKey: undefined, ... })` does NOT throw at construction (unlike `new Groq({ apiKey: undefined })`, which throws immediately). Used `process.env.NVIDIA_API_KEY || 'unset'` for the client construction, then added an explicit guard inside `executeOnProvider` that throws `'NVIDIA_API_KEY not configured'` before calling NIM — and extended the fallback-loop catch condition (previously only `isRateLimit(err)`) to also match this message, so missing-key correctly triggers `nim → groq1 → gemini` fallback instead of hard-failing.
- **NIM reasoning models (MiniMax-M2.7, Nemotron-49B) consume `max_tokens` on hidden reasoning** before producing `content`. With `max_tokens: 10` both returned empty/`undefined` content; with `max_tokens: 100`+ they returned correct content plus a separate `reasoning_content` field (not wrapped in `<think>` tags, so `stripThinkTags` is a no-op for them — harmless). The configured route `maxTokens` values (512-2048) are comfortably above this floor.
- `getVisionModel()` in `gemini.js` was preserved as a factory returning `{ generateContent(parts) }` — same contract `routes/ai.js` already calls (`parts = [{inlineData:{data,mimeType}}, {text}]` → `{response:{text()}}`). This let the NIM vision swap + Gemini fallback live entirely inside `gemini.js` without touching `routes/ai.js`.
- No `.env.example` exists in this repo — `NVIDIA_API_KEY` (with the `build.nvidia.com/settings/api-keys` comment) was added directly to `backend/.env` only.
